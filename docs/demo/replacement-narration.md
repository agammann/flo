## 0:00–0:12 — Problem

"Repair work shouldn't stop every time someone needs to search a business system.
Flo is an open-source MCP operating layer for hands-free service operations. This
demo shows a custom shop simulation and a separate hosted customer site."

## 0:12–0:32 — Hosted identity and ownership

"Here, Login with Amazon identifies the customer. Shop verification independently
controls access. Our approved fictional customer can read repair 1842, but not
another customer's repair. Sign-out removes access. These hosted test records are
separate from the shop simulation and have no estimate yet."

Capture actual hosted 1842/2842 responses. Keep identity, consent account details,
codes and tokens outside the frame. No pairing grant is needed for the already
linked test account; do not re-enable operator permissions for filming.

## 0:32–1:02 — Local MCP and ranking

"Now the local shop simulation. Open work order 1842. The alternator failed.
Find compatible replacements under three hundred dollars arriving tomorrow.
Flo executes MCP tools across mock shop, inventory and supplier services.
The balanced choice costs 219 dollars. The highest gross part profit comes from
the 289-dollar option: 101 dollars and 15 cents. That's profit in dollars, not
margin percentage."

Show exact commands and real tool results; retain the local/simulated-data label.

## 1:02–1:25 — Estimate and approval

"Add that option to the estimate and request approval. Deterministic pricing gives
a total of 561 dollars and 33 cents. The local customer preview hides shop costs.
We explicitly simulate customer approval here; no real customer message is sent."

If actual results differ, stop and reconcile the chosen part and environment;
do not edit the displayed amount or substitute the balanced 459.03 total.

## 1:25–1:40 — Resume

"Start a new conversation: what happened with the Ford? Flo resumes the approved
job from context. This shop state survives conversation changes, but is still
in-memory—not durable across a service restart."

## 1:40–2:12 — Transaction boundary

"Order the alternator and schedule Bay 2 tomorrow morning. First, Flo prepares
a summary. It has not placed the order. Confirm. The server rechecks approval,
the selected offer and schedule availability before executing the mock order
and reservation. A repeated confirmation cannot create another purchase."

Show the actual pending summary, result and duplicate rejection. Use the current
generated dates. Neither hosted customer fixtures nor real suppliers are mutated.

## 2:12–2:40 — Architecture and limits

"MCP connects the tools; deterministic code owns money, fitment and authority.
AWS hosts the separate customer identity and repair projections. A deployed
Bedrock narrator can add a bounded summary with local fallback. AgentCore and
official Alexa account linking, device testing and certification remain future
work. The browser demo is not Amazon's official simulator."

Use only dated AWS evidence or an actual approved call. Do not display a new
successful AWS trace when the local fallback ran.

## 2:40–2:50 — Close

"Flo makes the workflow inspectable, resumable and confirmation-gated. The MIT
repository includes the source, Docker setup, tests and honest integration limits."
